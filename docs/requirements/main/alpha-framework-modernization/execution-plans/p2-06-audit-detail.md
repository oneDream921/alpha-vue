# P2-06 审计详情增强执行计划

## 目标与边界

在不把原始请求体、响应体或认证敏感信息写入审计库的前提下，为带有 `@OperationLog` 的入口默认提供有限排障摘要；敏感或无需采集的入口通过注解关闭。登录、密码、验证码、令牌、文件、上传、密钥相关入口硬性禁止摘要采集。

## 安全评审结论

- `@OperationLog` 的 `saveRequest` 和 `saveResponse` 默认开启；入口可显式设置为 `false`，硬性禁采集规则始终优先。
- 请求摘要使用 Jackson 树递归清理敏感字段，限制深度、字符串长度和数组数量；Servlet、响应流和 Multipart 文件只记录 `[omitted]`。
- 响应只保存类型、状态和数据形状；列表只保存数量，不保存记录内容。
- 采集或序列化失败直接丢弃摘要，不回退保存原文。
- 列表接口不返回详情字段；详情通过 `log:operation:detail` 权限访问，并由操作日志记录查看行为。

## 实施结果

1. `sys_oper_log` 新增 `request_summary`、`response_summary`，通过 Flyway V25/V26 追加迁移。
2. 新增 `GET /api/logs/operations/{id}` 详情接口和独立权限。
3. 部门、角色新增和更新作为首批普通管理白名单入口；认证、文件和敏感管理接口保持关闭。
4. 前端详情弹窗改为按权限请求单条详情，列表不再携带异常堆栈。
5. 用户新增和更新接口显式开启请求/响应摘要；用户删除、角色授权和强制下线保持默认采集，密码重置继续关闭。
6. 响应摘要序列化器补充 Java 时间类型支持，修复用户响应包含 `LocalDateTime` 时摘要为空的问题。

## 验证

- 后端 `AuditDetailSanitizerTests`、`OperationLogAspectTests`、`LogControllerTests` 通过；用户模块相关回归测试通过，响应摘要共 18 项相关测试通过。
- 前端 typecheck 和全量 Vitest 通过。
- 用户人工验收通过：请求摘要可展示脱敏参数，普通对象响应显示 `dataKind: object`，无返回体操作显示 `dataKind: null`。
