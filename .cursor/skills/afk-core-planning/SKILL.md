# 规划

## 入口

- 已有《需求对齐稿》且用户选择「先做实施规划」，或用户明确要求 Plan / 实施方案 / 技术方案 → 使用本 Skill。不要依赖某个固定选项字母。
- 用户已授权实现，且改动复杂、跨模块，或涉及迁移、兼容、灰度、回退等真实风险 → 先使用本 Skill，再连续实现；原实现请求已经授权后续编码，不重复确认。
- 用户已授权简单、路径清晰且低风险的实现 → 可以不进入正式 Plan，动手前仍简要说明改动范围与验证方式。
- 需求目标、非目标仍模糊 → 先引导 `requirements-explore`，不要直接拆实施任务。
- 缺关键信息时：每轮最多 3～5 个确认问题，补齐后再规划。
- 需求已经确认时，连续完成方案选择和任务拆分；普通技术细节由 Agent 依据现有代码与规则判断，不要每拆一步都停下来要求用户决定。

规划是实施准备动作，Plan 是它默认留在对话中的产物，`design.md` 是可选留档；三者不是先后必经阶段。形成 Plan 或技术方案都不自动授权实现；只有用户已明确要求实现、按方案开发等动作时才继续编码。

## 步骤

1. 阅读相关规则与记忆索引（按需下钻）。
2. 确认范围、约束与验收标准；列出非目标。
3. 存在真实技术取舍时比较可行方案并明确选择；路径明显唯一时直接说明选择依据，不虚构备选。
4. 拆成小型实施任务；每项写清改动范围与验证方式。
5. 用户明确要求形成技术方案时，按下文边界把稳定的方案结论写入 `design.md`。
6. 用户已授权实现时，简要说明设计思路、改动范围与影响点后连续实施；只要求 Plan 或技术方案时输出后结束。

## 输出

- 选定方案（一句话；存在真实备选时再说明取舍）
- 任务列表（有序；每项包含任务目标、改动范围与验证方式，并可独立验证）
- 风险 / 需用户确认项（若有）

Plan 默认留在当前对话中，不创建 `plan.md` 或 `task.md`，也不引入任务状态、负责人或依赖管理。需要跨会话或交接且用户明确要求留档时，把稳定的实施顺序按需写入 `design.md`；执行进度仍在当前会话和最终交付中报告，不把动态状态写成新的需求事实源。

## 可选的技术方案文档

技术方案文档不是必经步骤。只有用户明确说「形成技术方案」「编写技术方案」「把方案写入需求目录」等时，才写入 `docs/requirements/<分支>/<slug>/design.md`；仅说「做个 Plan」「给个方案」「开始实现」不视为落盘授权。

落盘前按 Git 约定确认目标仓和受保护分支，并优先使用 `docs/requirements/_template/design.md`。若对应 `requirement.md` 存在，它是“做什么”的唯一依据；`design.md` 只能解释“怎么做”，不得重新定义目标、规则或扩大范围。若没有已落盘需求文档，写明方案依据来自用户已确认的对话、PRD 或其它规格，不自动补建 `requirement.md`。

技术方案保持短小，只回答：

- 依据什么需求；
- 选择什么方案以及关键取舍；
- 改动哪些模块、接口或数据；
- 如何处理实际存在的兼容、迁移、失败或回退风险；
- 如何验证技术方案正确实施，不重复 `requirement.md` 的业务验收标准。

需要跨会话实施或交接时，可以增加「实施顺序」，记录任务目标、改动范围和验证方式；不写负责人、进行中 / 已完成等动态状态。Plan 中始终包含任务列表，但普通技术方案不为形式强制落盘全部任务。

没有相关内容时不生成空小节，不强制方案数量、文件清单、任务编号或状态机。详细 DDL 如需落盘，先遵循项目 Rule 的明确约定，未配置时复用仓库已有 SQL 目录，仍无事实依据时才兜底 `scripts/sql/<分支>/<slug>.sql`；从 `design.md` 相对链接。

写完 `design.md` 后默认结束，不自动创建 `acceptance.md` 或开始编码；用户在同一轮明确要求「形成技术方案并实现」「按方案开发」等时，在方案落盘后连续实施，不重复确认。需求变化时检查并提示技术方案受影响之处，不自动修改需求基线。

方案涉及多人验收、较大回归、迁移核对或多环境组合时，可以把「形成测试验收文档」列为可选方向，但不得自动触发。

## 边界

- 用户只要求 Plan 或技术方案时不写业务代码；已经明确要求实现时，规划完成后连续实施。
- 不代替 `requirements-doc` 落盘需求文档；不代替 `update-memory` 写记忆。
- 不因技术问题需要解决就强迫用户形成 `design.md`；文档可选，关键决策不可省略。
- 实施收尾可依 `interaction` 把「提交交接」或「形成记忆」列为可选方向，并给出简短推荐；提交交接使用 `git-handoff`，由用户本地执行命令。
