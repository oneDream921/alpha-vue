# Alpha Vue 前端开发规范

> 状态：已确认，自 2026-07-27 起生效
>
> 适用范围：`alpha-web` 及其测试代码

## 1. 目标与原则

本规范用于保持 Alpha Vue 前端在持续扩展时仍具备清晰边界、稳定交互和可验证性。规则按以下优先级执行：

1. 正确性、安全性和可访问性优先于代码复用。
2. 沿用项目已采用的 Vue 3、TypeScript、Ant Design Vue、Pinia、Vue Router、Axios、Vite 和 Tailwind CSS，不因通用模板切换技术栈。
3. 按业务领域组织代码，按职责划分层次；先识别真实复用，再提取抽象。
4. 重构不得改变接口契约、权限语义和用户可见行为，除非任务明确要求。
5. 目录按需要创建，不预建空目录，不为追求形式统一拆分小文件。

## 2. 技术基线

| 范围 | 约定                                                      |
| ---- | --------------------------------------------------------- |
| 框架 | Vue 3 Composition API、`<script setup lang="ts">`         |
| 类型 | TypeScript 严格模式，禁止使用 `any` 绕过检查              |
| UI   | Ant Design Vue 负责表格、表单、弹窗、抽屉、上传等业务控件 |
| 样式 | Tailwind CSS、CSS Variables 和少量局部 CSS                |
| 状态 | Pinia，仅保存跨页面或跨会话状态                           |
| 路由 | Vue Router，受控组件白名单与后端菜单共同决定业务路由      |
| 请求 | Axios，只能由 `service` 层直接使用                        |
| 测试 | Vitest、Vue Test Utils、Axios Mock Adapter                |
| 构建 | Vite，包管理器统一使用 pnpm                               |

禁止混入 Element Plus 或第二套同类 UI 组件库。新增依赖必须说明现有能力无法满足的原因、体积影响和维护成本。

## 3. 目录与模块边界

### 3.1 目标结构

目录随业务增长渐进形成，允许尚未达到拆分条件的页面继续保留为单文件。

```text
alpha-web/src/
├── assets/                     # 构建期静态资源
├── components/                 # 跨页面复用的业务组件
├── composables/                # 跨页面复用的有状态组合逻辑
├── directives/                 # Vue 自定义指令
├── layouts/                    # 应用级布局
├── router/                     # 路由定义、守卫和动态路由管理
├── service/                    # HTTP 客户端、接口契约和领域 API
│   ├── http.ts
│   └── system/
│       ├── shared.ts
│       ├── users.ts
│       ├── roles.ts
│       ├── menus.ts
│       ├── depts.ts
│       ├── configs.ts
│       ├── dicts.ts
│       └── index.ts
├── stores/                     # 全局或跨页面状态
├── styles/                     # 设计令牌和全局样式
├── utils/                      # 无 Vue/业务状态依赖的纯工具
└── views/                      # 路由页面，按领域组织
    └── system/
        └── users/
            ├── index.vue
            ├── components/     # 仅用户页复用的组件
            ├── composables/    # 仅用户页使用的组合逻辑
            └── *.test.ts
```

### 3.2 职责

- `views`：负责路由页面布局、交互编排和业务反馈，不直接调用 Axios，不承载可独立测试的大段纯逻辑。
- `components`：只放两个及以上页面实际复用的组件。仅一个页面使用的组件放在该页面目录内。
- `composables`：封装具有 Vue 响应式状态或生命周期的复用逻辑；纯函数进入 `utils` 或所属页面模块。
- `service`：定义请求/响应类型和 API 调用，不管理页面 loading、弹窗或提示消息。
- `stores`：保存认证、权限、主题等跨页面状态；页面筛选、表单和弹窗状态默认留在页面。
- `router`：维护静态路由、受控业务路由白名单和守卫，不实现业务请求流程。
- `styles`：维护全局设计令牌与真正通用的布局模式，页面特有样式使用 `scoped`。

依赖方向应保持为：`views/components -> composables/stores/service/utils`，`service -> http`。底层模块不得反向依赖页面。

### 3.3 拆分条件

满足以下任一条件时，应评估拆分；拆分必须产生清晰职责，而不是只为降低行数：

- 一个页面同时管理两个及以上独立弹窗、抽屉或表单流程。
- 页面包含可独立命名、独立输入输出和独立测试的业务区块。
- 同一交互逻辑已在两个位置重复，或确定将在当前任务中复用。
- 单文件超过约 300 行且状态、请求、表格列和弹窗逻辑相互交织。
- 单个 service 文件包含三个及以上业务资源或持续发生多人修改冲突。

拆分后，路由页面 `index.vue` 仍负责流程编排；不要把页面全部搬进一个过大的 `useXxxPage`。

## 4. 命名与文件约定

| 类型         | 规则                              | 示例                            |
| ------------ | --------------------------------- | ------------------------------- |
| Vue 组件     | PascalCase                        | `UserFormModal.vue`             |
| 路由页面目录 | kebab-case 或领域资源复数         | `system/users/index.vue`        |
| 组合式函数   | `use` + PascalCase 语义           | `useUserPage.ts`                |
| 普通 TS 文件 | camelCase；领域资源可用复数小写   | `formatDate.ts`、`users.ts`     |
| 类型/接口    | PascalCase                        | `UserCreate`、`PageResponse<T>` |
| 常量         | UPPER_SNAKE_CASE                  | `DEFAULT_PAGE_SIZE`             |
| 布尔变量     | `is`、`has`、`can`、`should` 前缀 | `isLoading`、`hasPermission`    |
| 事件编排函数 | `handle` 前缀                     | `handleSubmit`                  |
| 单一动作函数 | 动词直接命名                      | `loadUsers`、`openEditor`       |

其他约定：

- API 方法使用明确动作，如 `page`、`get`、`create`、`update`、`delete`、`assignRoles`。
- 避免 `data`、`info`、`item` 等脱离上下文后含义不清的公共名称。
- 测试文件与被测模块相邻，命名为 `*.test.ts`。
- 导入统一使用 `@/` 指向 `src`；同一小模块内部允许使用相对路径。

## 5. Vue 与 TypeScript

- 新组件使用 Composition API 和 `<script setup lang="ts">`，顺序保持为 script、template、style。
- props、emits、模板引用、API 数据和表单模型必须有明确类型。
- 未知异常使用 `unknown`，通过 `axios.isAxiosError`、`instanceof` 或类型守卫收窄。
- 不使用非空断言掩盖未初始化状态；优先调整数据模型或显式分支。
- 派生状态使用 `computed`，避免用 `watch` 同步可直接计算的数据。
- 副作用在卸载时清理，包括事件监听、定时器和未完成的订阅。
- 模板中不写复杂表达式，不在渲染表达式中赋值或触发副作用。
- 只给非显然的业务约束和复杂算法写注释，不复述代码。

## 6. Service 与接口契约

- 页面和组件不得直接导入或调用 Axios；统一从 `@/service/...` 获取类型与 API。
- `http.ts` 只处理通用能力：base URL、超时、Token 注入、会话失效和通用网络错误。
- 领域 service 只描述请求，不显示 `message`、Modal，不持有页面状态。
- 通用响应使用 `ApiResponse<T>`，分页使用 `PageResponse<T>`；字段名必须与后端契约一致。
- 新增和更新模型分开定义；只有字段确实一致时才共享类型。
- 路径参数和请求体不得使用字符串拼接生成 JSON 等临时协议。
- 领域模块通过 barrel 文件提供稳定入口。重构 service 时，现有 `@/service/system` 导入在迁移期必须继续可用。
- 认证、文件、日志、监控与系统管理 API 保持领域隔离，不合并成全局 API 对象。

## 7. 状态、请求与错误处理

- 认证状态只有一个来源；Token、profile、permissions 和 routes 必须整体写入或整体清空。
- 页面首次进入和用户刷新时请求后端；新增、编辑、删除、上传、分配成功后重新请求权威数据。
- 每个可并发的数据区维护独立 loading，避免一个请求冻结无关区域。
- 使用 `try/finally` 恢复 loading。失败时保留已有数据，不清空为假空状态。
- 请求层负责 401、网络错误等通用反馈；页面只补充业务上下文，不重复弹出同一错误。
- 退出登录、删除及其他破坏性操作必须先经用户二次确认；删除确认文案应指出对象和影响，退出登录确认文案应说明需重新登录。
- 禁止在日志、URL、错误提示或本地调试输出中暴露 Token、密码、验证码和敏感表单。

## 8. 权限与路由

- 后端授权是唯一安全边界；前端权限只改善导航和操作展示。
- 页面路由由前端组件白名单与后端菜单共同匹配，未知组件标识必须拒绝注册。
- 路由 `meta.permission`、后端菜单权限码和按钮 `v-permission` 使用同一 `domain:resource:action` 语义。
- 业务按钮使用 `v-permission`；仅在非 DOM 流程判断中调用 `authStore.hasPermission`。
- 会话切换或退出时必须移除动态业务路由，不能残留上一用户权限。
- 403 与 404 分开处理；未登录、无权限和不存在不得混为同一跳转。

## 9. 页面与组件交互

列表页按“标题与主要操作、筛选/工具栏、数据区、分页、弹窗/抽屉”组织：

- 标题区只放页面名称和主要操作，不使用营销式大标题。
- 列表必须有明确刷新入口；筛选重置后回到第一页。
- 表格列设置稳定宽度或最小宽度，并配置横向滚动；操作列在桌面端保持可达。
- 表单使用 Ant Design Vue 校验规则；服务端返回前仍需执行客户端边界校验。
- 弹窗适合短表单，复杂流程或窄屏长表单优先抽屉；关闭时清理校验与临时状态。
- 工具按钮使用 `@ant-design/icons-vue`，仅图标按钮提供 `aria-label` 和 `title`。
- 使用中文 locale、校验、分页、空状态和确认文案，不残留英文默认文本。

## 10. 响应式与可访问性

- `>= 1024px`：桌面侧栏可展开或折叠。
- `768px - 1023px`：默认紧凑布局，表格允许横向滚动。
- `< 768px`：侧栏使用抽屉，筛选和表单单列，操作可收纳到菜单但不得删除能力。
- 所有视口至少支持 320px 宽度；文字不得与按钮、表格或后续内容重叠。
- 交互控件必须可通过键盘到达，并保留清晰焦点状态。
- 图片提供有意义的 `alt`；纯装饰图片使用空 `alt`。
- 不用颜色作为状态的唯一表达；必要时同时提供文本或图标。

## 11. 样式与设计令牌

- 颜色、圆角、阴影、画布和尺寸优先使用 `styles/tokens.css` 中的 `--alpha-*` 令牌。
- Ant Design Vue 管理业务控件视觉；不要用全局 CSS 大范围覆盖其内部实现类。
- Tailwind/CSS 用于布局、间距和响应式组合，不重复造按钮、输入框、表格和弹窗。
- 页面区块不嵌套装饰卡片；管理页面保持紧凑、易扫描，卡片仅用于真正独立的重复内容。
- 页面特有选择器放在组件 `scoped` 样式；两个以上页面稳定复用后再上移全局样式。
- 圆角默认不超过设计令牌 `--alpha-radius`，避免无业务意义的渐变和装饰图形。

## 12. 测试与交付

测试投入按风险分配：

- 纯函数、分页状态、校验和权限映射优先写单元测试。
- service 变更测试 HTTP 方法、路径、参数和请求体，不只验证返回值。
- store 测试整体会话写入、持久化、失效清理和异常存储环境。
- 路由测试组件白名单、权限匹配、动态注册和清理。
- 页面拆分至少覆盖关键提交、取消、错误和权限隐藏流程；不依赖脆弱的 DOM 快照作为唯一断言。

每个独立任务至少运行聚焦测试和 `typecheck`。阶段交付运行：

```bash
pnpm --dir alpha-web typecheck
pnpm --dir alpha-web test
pnpm --dir alpha-web lint
pnpm --dir alpha-web format:check
pnpm --dir alpha-web build
git diff --check
```

涉及页面和布局时，还需在桌面、平板和手机尺寸完成浏览器验收，检查加载、空状态、错误状态、权限、横向滚动和所有操作可达。

## 13. 变更检查清单

- 文件放置符合所属领域和职责，没有为了“看起来完整”新增空目录。
- 页面未直接调用 Axios，service 未包含 UI 状态或消息提示。
- 没有 `any`、敏感日志、权限旁路或未清理副作用。
- API 类型、路径、请求方法和后端契约一致。
- 新增/更新/删除成功后重新获取权威数据，失败时保留原数据。
- 桌面和移动端能力一致，文字与控件无重叠。
- 新增图标来自现有图标库，图标按钮具有可访问名称。
- 聚焦测试与阶段质量检查通过。

## 14. 例外处理

确需偏离本规范时，在对应设计或执行计划中记录：偏离规则、原因、影响范围、替代保护和后续清理条件。临时例外不得无期限存在。
