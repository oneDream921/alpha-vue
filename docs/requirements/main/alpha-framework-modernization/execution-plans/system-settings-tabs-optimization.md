# 系统配置 Tab 优化执行计划

## 目标与边界

在现有 8 个配置组与 API 路径不变的前提下，使系统配置页具备清晰的信息分区、准确的能力/生效说明、可靠的加载与保存状态、条件字段联动、敏感字段保护以及桌面/平板/手机可操作性。

不新增数据库迁移，不扩展真实支付、OAuth、微信或对象存储连通性测试，不改变密文格式和权限码。

## 实施顺序

1. 为每个配置组补充服务端值校验，拒绝非法枚举、类型、范围、URL、扩展名和 JSON，保持敏感字段留空即保留原值。
2. 重组设置页的信息架构，为每组展示用途、生效方式和当前能力边界；补齐条件字段与文件私有链接有效期。
3. 消除切换时的请求竞态，补充加载失败重试、脏状态、放弃修改确认、重置与保存后权威重载。
4. 收紧 RSA 一次性私钥和公众号发布动作的前置状态，避免把未保存内容误认为已生效。
5. 增加聚焦测试，并完成前后端质量检查、HTTP 验收和 1440/768/375 浏览器验收。

## 兼容与风险

- API 路径、请求/响应结构、权限和数据库数据结构保持兼容；已有合法配置可继续读取。
- 新校验只影响后续非法保存，统一返回 400，不回显内部原因或敏感值。
- 外部平台能力没有本地凭据时仅验证托管与前置条件，不宣称真实联调通过。
- 回滚只需回退代码，数据库无结构性变化。
