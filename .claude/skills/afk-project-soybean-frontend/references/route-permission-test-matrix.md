# 路由与权限测试矩阵

## API/service

验证领域 service 使用真实后端契约：

- HTTP 方法、路径参数、查询参数和请求体正确。
- Alpha 响应 envelope（`code`、`message`、`data`、`traceId`）适配正确。
- 401、网络错误和业务错误由请求层与页面分工处理，不重复提示或泄露敏感信息。

## 动态路由

至少覆盖：

- 后端菜单到 Elegant Route 的转换，包含 `layout.base$view.*`、`view.*` 和隐藏认证路由。
- 组件标识只允许来自受控组件白名单；未知组件拒绝注册并产生可诊断错误。
- 固定路由、登录页、403、404 和后端业务路由的跳转边界。
- 刷新、会话切换和退出登录后，旧用户的动态路由、菜单和标签页不会残留。
- 新页面文件变更后已运行 `pnpm gen-route`，生成导入和类型与实际文件一致。

## 权限

- 后端授权是安全边界；前端 `v-permission` 只负责隐藏或禁用体验。
- 页面、菜单和按钮权限码保持同一 `domain:resource:action` 语义。
- 无权限用户不能通过直接输入 URL、刷新或手动调用页面动作绕过后端授权。
- 403 与 404 分开呈现；未登录、无权限和不存在的资源不混用同一跳转。
- 破坏性操作有二次确认，失败后保留原数据并显示业务上下文。

## Store/session

- 登录成功时 token、profile、permissions 和 routes 整体写入；任一关键步骤失败时不留下半套会话。
- 401、退出登录和会话切换时整体清理认证状态、动态路由和相关持久化数据。
- 持久化不可用或损坏时有可诊断的降级行为，不把 token、密码、验证码写入日志。

## 页面验收

- 验证有权限、无权限、未登录、403 和 404 至少各一条真实路径。
- 关键操作覆盖成功、校验失败、服务端失败、取消和重复提交。
- 真实浏览器检查 URL/DOM/截图/控制台；涉及布局时检查桌面、平板和移动视口。
- 不把脆弱 DOM 快照作为唯一断言；优先断言路由状态、权限结果、请求契约和用户可见状态。
