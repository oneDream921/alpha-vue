# Alpha Vue 数据字典设计

## 目标与范围

本里程碑新增可由后台维护的数据字典，用于统一管理后续业务字段的可选值。首期提供字典类型、字典项的受 RBAC 保护的 CRUD，以及供已登录业务模块读取启用项的只读接口。

本期不改造用户、菜单、日志等已有页面去使用字典；不实施 Redis 管理，也不引入运行时缓存或热更新机制。

## 方案选择

采用独立的 `sys_dict_type` 与 `sys_dict_item` 两表，而非单表父子结构：类型与字典项的字段和约束分明，能可靠地保证类型编码全局唯一、同一类型内字典项值唯一，并支持后续按类型查询。

前端采用一个 `/system/dicts` 管理页面。左侧为可筛选的字典类型，右侧为当前选中类型的字典项；不为本期创建新的业务页面改造任务。

## 数据模型与约束

### 字典类型

`sys_dict_type` 包含下列业务字段：

- `type_code`：全局唯一的类型编码，创建后不可修改；
- `type_name`：类型名称；
- `status`：启用或停用；
- `remark`：备注。

表同时继承项目既有审计字段与逻辑删除字段。逻辑删除记录不参与类型编码唯一性校验。

### 字典项

`sys_dict_item` 通过 `type_id` 关联字典类型，包含：

- `label`：展示标签；
- `value`：字符串值；
- `sort_order`：升序排序值；
- `status`：启用或停用；
- `is_default`：默认标识；
- `remark`：备注。

同一类型内，未删除字典项的 `value` 必须唯一。字符串值同时兼容 `enabled`、`draft`、`1` 等枚举形式。首期允许同一类型有多个默认项，以免引入未被业务需要的唯一默认项规则。

删除字典项使用逻辑删除。删除字典类型前，服务必须检查其是否仍有未删除字典项；如有，拒绝删除并返回“请先删除该字典类型下的字典项”。停用类型或字典项后，业务读取接口均不得返回对应字典项。

## 后端设计

后端按现有 Entity、DTO、VO、Service、Mapper Interface、Mapper XML 分层实现。新增 Flyway 迁移，不修改历史迁移；迁移创建两张表、必要索引、中文菜单“数据字典”和权限，并将权限授予 `SUPER_ADMIN`。

管理接口位于 `/api/system`：

```text
GET    /dict-types
GET    /dict-types/{id}
POST   /dict-types
PUT    /dict-types/{id}
DELETE /dict-types/{id}

GET    /dict-types/{typeId}/items
POST   /dict-types/{typeId}/items
PUT    /dict-items/{id}
DELETE /dict-items/{id}
```

类型列表与字典项列表采用现有分页契约。类型创建与更新校验类型编码；更新时拒绝修改 `typeCode`。字典项创建和更新校验其所属类型存在，以及该类型内 `value` 的唯一性。公共错误保持中文，例如“字典类型编码已存在”“字典项值已存在”。

业务读取接口为：

```text
GET /api/system/dicts/{typeCode}/items
```

该接口要求已登录，但不要求 `system:dict:list`。它按 `sortOrder` 升序返回启用类型下的启用字典项，只暴露 `label`、`value`、`sortOrder`、`isDefault` 等展示安全字段，不返回备注、审计字段或管理状态。

## 权限与审计

管理接口使用下列权限：

- `system:dict:list`
- `system:dict:create`
- `system:dict:update`
- `system:dict:delete`

前端页面和操作按钮按对应权限展示，后端作为最终安全边界。类型与字典项的创建、更新、删除均添加 `@OperationLog`。审计仅记录业务对象、操作类型与结果，不记录完整请求体或表单值。

## 前端设计

新增 typed service 和 `/system/dicts` 路由，并在受控路由白名单、固定中文导航中接入“数据字典”。页面沿用参数配置现有的查询、分页、权限、表单验证、确认删除和错误提示模式。

类型未选中时不请求或展示字典项；切换类型后刷新右侧列表。类型删除仅在后端确认无有效字典项时成功，前端直接展示中文错误反馈。

## 验证与验收

后端测试覆盖：

- 类型和字典项的 CRUD、分页与详情；
- CRUD 权限拒绝；
- 类型编码、类型内字典项值唯一性；
- 已停用类型或字典项不出现在业务读取接口；
- 类型删除依赖校验；
- 写操作审计与不记录完整表单值。

前端测试覆盖权限可见性、表单必填与长度校验、类型切换、字典项提交。完成实现后，必须使用项目 Maven 路径运行后端全测；前端运行 test、typecheck、lint、format、build；全部通过后启动服务供人工验收。

## 明确不在本期实现

- 将既有业务字段迁移到数据字典；
- 匿名访问字典读取接口；
- Redis 缓存、Redis 管理或自动刷新；
- 类型编码修改、字典项物理删除、强制唯一默认项；
- 字典导入导出、分级字典或多语言字典。
