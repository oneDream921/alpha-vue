# 调试排查

1. **复现**：记录预期行为与实际行为，给出最小复现路径（步骤、输入、环境）。
2. **取证**：用日志、失败测试、代码路径缩小故障边界；先读再猜。
3. **根因**：在动手前定位根因；区分症状修复与根因修复。
4. **按意图停止或继续**：用户只要求排查、解释或定位时，输出复现证据、根因、影响与修复建议后停止，不修改文件。仅用户明确要求修复时继续。
5. **改前确认**：删除现有逻辑、大范围数据变更、或改持久化映射 / 原始 SQL 前，先说明影响并获得确认（与安全/工程约定一致）。
6. **修复与回归**：选最小且安全的修复；新增或更新回归测试，再跑受影响检查。
7. **收尾**：若根因涉及业务认知偏差，可在 `[下一步建议]` 中推荐「形成记忆」并说明理由；勿自动写记忆。

## 不要做

- 未复现、无证据时大范围改代码。
- 把“帮我排查 / 定位原因”自动解释成“直接修复”。
- 把排查阶段变成新功能需求探索（那是 `requirements-explore`，投影：`afk-core-requirements-explore`）。
