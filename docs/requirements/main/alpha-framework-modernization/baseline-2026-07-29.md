### 3.2 当前配置事实

- `application-dev.yml` 和 `application-prod.yml` 均显式配置 `DruidDataSource`。
- 开发环境默认启用 Druid 页面，生产环境默认关闭。
- Redis 连接池配置位于 `spring.data.redis.lettuce.pool`。
- Sa-Token 当前为 `is-concurrent=true`、`is-share=false`，尚无 `clientId` 会话维度。
- 开发环境启用 SpringDoc API JSON 和 Knife4j 页面。
- 生产环境关闭 SpringDoc、Knife4j 和 Druid 页面。
- 文件 Provider 默认值为 `local`，支持通过配置切换 MinIO。
- SQL 监控使用固定容量的进程内摘要，同时仍提供 Druid 入口。
- 项目不存在 p6spy 和 SkyWalking 依赖。

## 8. 已确认缺口与警告

### 8.1 功能缺口

1. 当前没有在线用户 Controller、接口或前端页面。
2. 已登录访问不存在的 `/api/monitor/online` 返回 HTTP 500 和通用“服务器内部错误”，而不是 404。
3. 登录请求和会话模型没有 `clientId`、设备维度和定向下线能力。
4. 前端 Vite 代理地址固定为 `localhost:8080`，本机端口冲突时不能通过环境变量切换。

### 8.2 非阻断警告

1. Flyway 提示当前 H2 2.4.240 高于其已验证的 2.3.232。
2. 真实 MySQL 启动时，Flyway 提示 MySQL 8.4 高于其已验证的 8.1。
3. macOS 环境缺少 Netty 原生 DNS resolver，回退到系统实现。
4. Mockito 当前通过动态加载 Byte Buddy agent 工作，未来 JDK 可能默认禁止。
5. Vitest 在 Node 26 下提示没有提供 `--localstorage-file`，但测试全部通过。
6. 前端主入口 chunk 超过 Vite 默认体积提示阈值。

这些内容均为当前基线事实，不在 S0-01 中顺手修复。
