# P2-03 Redis 监控增强执行计划

## 目标与边界

在现有 Redis 管理页上增加当前实例的内存、命令和连接诊断：应用每分钟只读采集一次 Redis INFO，内存中最多保留 1,440 个成功样本（24 小时）。排障目标是 10 分钟定位常见 Redis 异常。

不引入时序数据库、跨实例聚合、通用任务平台、任意 Redis 命令执行、批量删除、`KEYS`、`FLUSHDB` 或 `FLUSHALL`。前端图表使用 ECharts；既有概览、受限 SCAN、敏感值脱敏、单键删除、权限和审计语义保持不变。

## 当前基线

- 分支：`codex/p2-03-redis-monitoring`，基线 `2d2f394`，已合并到 `main`。
- 现有 `/api/monitor/redis/overview` 仅返回版本、运行时间、已用内存、连接数和键数；`/keys` 保持有界 SCAN，单键删除已有确认与审计。
- 前端使用 ECharts 实现命令统计、内存仪表盘和内存/命令吞吐/连接趋势图；图表容器支持恢复尺寸后的初始化和响应式调整。

## API 契约

| 方法 | 路径 | 权限 | 输入 | 成功数据 |
| --- | --- | --- | --- | --- |
| `GET` | `/api/monitor/redis/metrics` | `monitor:redis:list` | 无 | 采样状态、最后成功快照、Top 10 命令和最多 1,440 个趋势点 |

接口保持统一 `ApiResponse<T>`。禁用、首次采样或最近采样失败均返回 `200` 和明确状态；未登录返回 `401`，无权限返回 `403`。不得返回 Redis 地址、凭据、原始 INFO、键值或命令参数。

## 实施顺序

1. 在 `modules/monitor` 增加只读 INFO 来源、白名单解析、不可变指标模型与受限 Top 10 命令统计。
2. 增加仅此用途的 Spring 定时采样和线程安全环形缓冲；采样失败保留最后成功数据，不影响业务 Redis 路径。
3. 暴露受现有 `monitor:redis:list` 保护的 `/metrics` 接口，配置可用 `REDIS_METRICS_ENABLED=false` 关闭增强采样。
4. 扩展前端领域 service，在 Redis 管理页增加指标状态、趋势、Top 命令与独立 loading/error；增强区失败不阻断概览、SCAN 或删除。
5. 添加后端 INFO/采样/API 安全测试及前端 service/ECharts/页面状态测试。
6. 运行跨层验证、真实 HTTP 和用户三视口验收；根据实际证据更新 API、安全、开发、运维、实施计划和 G3 状态。
