# Git 提交交接

## 入口

- 用户说「提交」「commit」「帮我提交」「确认提交」、询问提交信息或选择「提交交接」。
- 实施与验证已完成，需要整理可审阅的提交边界。
- 仅讨论 Git 概念、查看历史或比较 diff 时不必使用。

## 步骤

1. 用只读命令确认目标仓、当前分支、`git status` 和完整 diff；多仓逐仓处理。
2. 当前在受保护分支时提示直接提交风险并推荐迁出；用户已明确表示不迁出、就在当前分支提交或只要提交命令时，记录该选择并继续生成命令，不重复阻塞。
3. 保留与当前任务无关的用户改动，按功能、修复、文档、重构、测试等逻辑主题分组。
4. 排除 `.env`、明文密钥、私钥、证书、依赖目录、构建产物及项目约定不应提交的文件。
5. 每批列出文件、建议 message 和一整条可复制命令。多批必须独立提交，不使用 `git add -A`。
6. 最后报告尚未验证、未纳入或需要用户复核的内容。Agent 到此停止，不执行命令。

## 命令格式

无 body 时：

```bash
git add <paths> && git commit -m "<type>(<scope>): <中文 subject>"
```

需要 body 时：

```bash
git add <paths> && git commit -m "$(cat <<'EOF'
<type>(<scope>): <中文 subject>

<中文 body>
EOF
)"
```

subject 使用动词开头，不以句号结尾，建议不超过 50 个汉字；type、scope 可保留英文惯例，subject 与 body 使用中文。格式调整与业务逻辑分开提交，每个提交只做一件事。

## 边界

- 不执行 `git add`、`git commit`、`commit --amend`、分支切换、合入、推送或历史改写。
- 不把用户的任何自然语言或选项选择解释为绕过 Git Hook 的授权。
- 生成单批或分批提交命令属于只读交付，不视为执行 Git 写操作，也不需要用户再说「确认提交」。
- 受保护分支上的风险提示不取消命令交付；用户明确选择留在当前分支后，可以生成该分支的命令，但必须注明分支风险。
