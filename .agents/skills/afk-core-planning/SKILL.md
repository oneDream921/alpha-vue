# 规划

## 入口

- 已有《需求对齐稿》且用户选择「先进入 Plan」，或用户已给出明确范围 / 验收标准 → 使用本 skill。不要依赖某个固定选项字母。
- 需求目标、非目标仍模糊 → 先引导 `requirements-explore`，不要直接拆实施任务。
- 缺关键信息时：每轮最多 3～5 个确认问题，补齐后再规划。
- 需求已经确认时，连续完成方案选择和任务拆分；普通技术细节由 Agent 依据现有代码与规则判断，不要每拆一步都停下来要求用户决定。

## 步骤

1. 阅读相关规则与记忆索引（按需下钻）。
2. 确认范围、约束与验收标准；列出非目标。
3. 比较可行方案，**明确选择其中一种**并简述取舍。
4. 拆成小型实施任务；每项写清改动范围与验证方式。
5. 动手前简要说明：设计思路、改动范围、影响点（与工程约定一致）。

## 输出

- 选定方案（一句话 + 为何不选备选）
- 任务列表（有序；每项可独立验证）
- 风险 / 需用户确认项（若有）

## 边界

- 本阶段默认**不写业务代码**（用户明确说「按 Plan 实现」后再实现）。
- 不代替 `requirements-doc` 落盘需求文档；不代替 `update-memory` 写记忆。
- 实施收尾可依 `interaction` 把「提交交接」或「形成记忆」列为可选方向，并给出简短推荐；提交交接使用 `git-handoff`，由用户本地执行命令。
