# Grill Me

对高影响决策做轻量的决策树访谈，不负责需求文档、Plan、测试或提交闭环。固定来源、改造说明和 MIT 许可见 `references/UPSTREAM.md`。本 Skill 定义 frontier 选人规则；`requirements-explore` 的分轮模式复用同一规则组题。

## 使用条件

- 用户明确要求 grill、逐题确认或一次只问一个。
- `requirements-explore` 已完成首轮分析，用户选择逐题模式。
- 简单事实查询、显然只有一个决定或需求已经完整时不要启用。

## Frontier（选人规则）

把未决高影响决策视为依赖树：某题的答案会改变另一些题是否成立或如何问法时，后者依赖前者。

**Frontier** = 前置决策已确认或可自行核实、且彼此无依赖的未决问题集合。按影响（范围、行为、数据、验收、不可逆风险）排序后取用；低影响细节可作暂定假设，不进入 frontier。

可查事实先自行核实，不向用户打听环境里能查到的信息。

## 循环

1. 继承并整理四类状态：已核实事实、已确认决策、暂定假设、未决问题；可查事实先自行核实。
2. 按上述规则计算 frontier；本 Skill 默认只取其中影响最大的一个未决问题，不一次展示整棵决策树。
3. 一次只提一个问题，列出实际互斥的短选项，并给出推荐和一句理由。
4. 用户回答后检查是否解决当前问题、是否与已确认内容冲突或扩大范围；必要时留在当前问题。
5. 锁定结论后重算 frontier，再进入下一题；需要继续时，先用一行写上一题结论。

问题和选项保持简短，方向沿用全局交互协议；常用形式如下：

```markdown
**Qn（短标签）**

一句话问题。

A. 短结论：考虑的方向
B. 短结论：考虑的方向

[下一步建议] 推荐选 A。推荐理由：一句简短理由
```

## 结束

- 高影响决策已解决或明确保留为风险后，输出共同理解摘要并结束本 Skill。
- 从 `requirements-explore` 进入时，把状态和结论交还给它输出正式对齐稿。
- 用户明确确认共同理解前，不执行实现、不写需求文档、不改项目记忆。
