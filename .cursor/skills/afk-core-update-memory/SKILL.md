# 更新项目记忆

**索引**：记忆根目录下的 `README.md`（只改导航/登记，不写长文）  
**分层**：`domains/` · `services/<名>/` · `contracts/`

## 提案前三问（必须）

1. 去掉类名、端口、构建命令后仍成立？→ **`domains/<domain>.md`**  
2. 两仓及以上或前后端边界线上的格式？→ **`contracts/<a>-<b>-<topic>.md`**  
3. 单仓构建、启动、包结构、类落点、本仓排查？→ **`services/<名>/overview.md` 或 `local-dev.md`**

答不上来时先问用户落哪一层，不准猜测，也不生成不完整提案。

## 第一阶段：形成提案

1. Read 索引 `README.md`，确定层与目标路径。
2. Read 目标文件；无则读取对应 `_template*.md`，但此阶段不创建文件。
3. 核实准备形成的内容；与代码冲突时以代码为准，争议未裁定的内容列入「不写入」。
4. 在对话中输出完整的《记忆变更提案 v1》；提案只供用户审阅，不写入项目记忆、需求文档或临时文件。
5. 用户提出调整时，重新输出完整的 v2、v3……；旧版本失效，不只汇报本轮差异。

提案使用以下紧凑格式：

```markdown
## 记忆变更提案 vN（尚未写入）

### 变更概览
- 新增：N 项
- 修改：N 项
- 删除：N 项

### 变更明细

1. [新增] `目标文件`「章节」
   - 添加：准备写入的实际内容
   - 依据：用户确认 / 代码核实 / 现有记忆

2. [修改] `目标文件`「章节」
   - 原内容：现有内容
   - 改为：准备写入的实际内容
   - 依据：用户确认 / 代码核实 / 现有记忆

3. [删除] `目标文件`「章节」
   - 删除：现有内容
   - 原因：删除理由

### 不写入
- 尚有争议或证据不足的内容；没有则写「无」

### 等待你的决定

你可以回复：

- `确认形成记忆`：按照当前 vN 提案写入项目记忆。
- `暂不形成`：结束本次记忆整理，不修改任何文件。
- 直接说明调整内容：例如“把第 2 项改成……”“删除第 3 项”“补充……”。我会重新输出完整的下一版本，仍不会写入文件。
```

格式要求：

- 新增、修改、删除三类必须全部出现；没有内容时明确写「无」。
- 新增写清「添加什么」；修改使用「原内容 / 改为」；删除写出原内容和原因。
- 标明目标文件与章节，只展示受影响的最小内容，不粘贴整个文件。
- 展示准备落盘的实际表述，不使用「补充相关说明」「清理旧内容」等模糊摘要。
- 删除整个章节或文件时，明确写「删除章节」或「删除文件」。

## 用户决定

| 用户输入 | 动作 |
| --- | --- |
| 单独、明确回复「确认形成记忆」 | 对最新完整提案执行第二阶段 |
| 「暂不形成」或同义表达 | 结束，不修改任何文件 |
| 提出任何调整 | 重新核实并输出完整的下一版本，继续等待确认 |
| 「确认形成记忆」同时带有调整 | 视为调整，不写入；先输出包含调整的下一版本 |
| 没有当前提案时直接说「确认形成记忆」 | 先生成 v1，不得直接写入 |

提案仅绑定当前对话中的最新完整版本；找不到该版本时必须重新生成，不得从零散讨论推断写入内容。

## 第二阶段：确认后写入

1. 收到有效的「确认形成记忆」后，重新 Read 目标文件；若内容已变化并影响提案，停止写入并生成新版提案。
2. 只执行最新提案列出的新增、修改和删除，不顺手润色、扩写或整理其他记忆。
3. 无目标文件时按对应 `_template*.md` 懒创建；新建文档时在 `README.md` 域注册表或导航中加一行链接。
4. 完成自检并汇报实际修改路径、新增/修改/删除数量、是否与提案一致；不得把提案本身保存成文件。

## 自检

- [ ] domains 中无 `.java` / `src/main` / 包路径堆砌  
- [ ] 启动/构建命令只在 `services/<名>/local-dev.md`  
- [ ] 跨端字段在 contracts，并与 domains/services 互链  
- [ ] 未新建未约定的第四层目录  
- [ ] README 已登记  

## 边界

- 用户要求形成记忆只授权生成提案，不授权落盘；只有针对最新完整提案的「确认形成记忆」才授权写入。
- 若尚在核对「现网 / 代码 / 记忆是否一致」，先走 `align-memory`（投影：`afk-core-align-memory`）；确认认知后再用本 skill 生成提案。
- 不把业务事实写进 `.project-agent/rules` 或框架托管文件。
