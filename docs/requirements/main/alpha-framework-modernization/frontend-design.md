# 前端设计

## 1. 设计目标

Alpha Web 学习 Vben5 的管理端信息架构、操作效率和细节完整度，但保持现有单应用和克制依赖：

- Vue 3
- TypeScript
- Vite
- Ant Design Vue
- UnoCSS
- Pinia
- Vue Router
- Axios

一期不因长期目标引入整套 VXE、ECharts、Iconify、Lucide 和 Playwright 组合。新增依赖必须绑定到明确任务、体积评估和验证场景。

## 2. 视觉与交互基准

- 以当前 `ruoyi-plus-vben5` 的侧边导航、顶部工具区、标签页、查询区、表格工具栏、抽屉表单和详情布局作为体验参考。
- 保留 Alpha Vue 名称、Logo、主题色和设计 Token。
- 不做逐像素复制，不引入 Vben 品牌或内部 Package。
- 管理页面保持安静、紧凑、易扫描，不使用营销式大标题和装饰性卡片堆叠。
- Ant Design Vue 负责业务组件；UnoCSS 和 CSS Variables 负责布局、间距和响应式。
- 所有视口保留同一业务能力，移动端只改变布局和操作入口。

## 3. 一期范围

### 3.1 目录整理

沿用现行 `service` 命名，不为形式统一强制改名为 `api`：

```text
src/
├── service/
│   ├── http.ts
│   ├── auth/
│   ├── system/
│   ├── monitor/
│   └── file/
├── components/
├── composables/
├── directives/
├── layouts/
├── router/
├── stores/
├── styles/
├── utils/
└── views/
```

要求：

- 拆分当前聚合多个资源的 Service 文件。
- 迁移期间保留旧 Barrel 出口，单独任务完成后再删除兼容出口。
- 不批量移动与当前任务无关的页面。
- 测试与被测模块就近放置。

### 3.2 登录与会话

登录表单：

- 固定提交 `clientId=pc-admin`。
- `clientId` 由前端应用配置提供，不让普通用户手工输入。
- 不展示 `clientKey` 或 `clientSecret`。

持久化：

- 未勾选“记住我”时 Token 写入 `sessionStorage`。
- 勾选时 Token 写入 `localStorage`。
- 只持久化 Token、`clientId` 和存储模式。
- profile、permissions 和 routes 在刷新时从后端重新获取。
- 401 并发响应只触发一次清理和跳转。

路由：

- 后端提供菜单元数据。
- 前端使用受控 `componentKey -> lazy import` 白名单。
- 未知组件拒绝注册。
- 按钮权限不生成路由。
- 小程序未来复用权限语义，不复用 Web 菜单。

### 3.3 列表页

当前统一使用 Ant Design Vue Table：

- 保持稳定列宽、横向滚动、刷新、搜索和重置。
- 通过轻量 `AlphaTableCard` 统一表格容器、工具栏、分页和横向滚动布局。
- 通过 `TableColumnSetting` 为需要的业务列表提供列显示和对齐方式设置。
- 菜单管理、部门管理、字典/通知类型列表不提供列设置；文件、参数、角色和用户列表按页面需要提供对齐设置。
- 不引入 VXE Table；不同时维护 Ant Table 与 VXE 两套长期列表规范。

### 3.4 日期与 ID

- 一期保持与当前后端契约兼容，不将时间格式迁移夹带到 Redis 或表格任务。
- 前端逐步集中日期格式化函数，停止页面散落 `new Date(...).toLocaleString(...)`。
- Snowflake 决策前，接口 ID 类型仍必须避免假设连续性。
- 若后续统一 Long 字符串，前端所有 ID 类型同步改为 `string`，不得混用 `number`。

### 3.5 UTF-8

必须覆盖：

- 菜单名称
- 部门名称
- 字典名称和值
- 登录地点和操作地点
- 登录与操作日志消息

接口响应、数据库连接、Flyway 文件、Java 源码、前端源码、HTML 和代理响应均使用 UTF-8。新增回归测试必须包含中文数据，不能只用 ASCII Fixture。

## 4. 管理体验增强

### 4.1 表格与列设置决策

已完成 Ant Table 统一迁移和代表性列表验证：

- 列显示/隐藏和列顺序由 `TableColumnSetting` 管理。
- 当前列设置仅保存列显示、顺序和对齐方式，不提供固定列模式。
- 文件列表的复合文件名单元格会让图标与文件名整体跟随列对齐方式。
- 表格容器统一处理左右边距、横向滚动和分页布局。
- 菜单、部门、字典/通知类型列表保留固定的业务列，不显示列设置入口。

本次人工验收已由用户确认通过。后续只在出现明确复用需求时扩展轻量公共组件，
不建设 `AlphaGrid` 或通用 CRUD DSL。

### 4.2 业务组件

不预先登记 `AlphaPage`、`AlphaGrid` 等候选清单。只有页面结构、查询、表格、弹窗、状态、
确认或上传规则已经在至少两个真实页面稳定重复，才逐个提出公共组件设计。只服务一个页面
的组件留在页面目录，不以“后续可能复用”作为抽取依据。

### 4.3 Redis 监控

若 ECharts 引入：

- 命令调用 Top N。
- 内存占用。
- 命中、未命中、过期、淘汰等当前快照。
- Redis 基础描述信息。

一期不保存历史时序；页面刷新获取新快照。图表失败不能阻止文本指标显示。

### 4.4 用户偏好

当前只实现浏览器本地偏好，不规划服务端或跨设备用户偏好同步：

- 列设置：保存在 `localStorage`，按页面使用稳定 `storageKey`，带 `version: 1`。
- 当前不会写入数据库，不支持跨浏览器、跨设备或跨账号同步；同一浏览器内不同账号会共享同一页面设置。
- 当前打开标签。
- 全屏。
- 移动抽屉。
- 侧边栏临时折叠。
- 查询条件和未提交表单。

规则：

- 按用户、`clientId`、类别和 Key 隔离。
- 本地缓存只作接口失败降级。
- 保存防抖。
- 多设备最后写入生效。
- Schema 版本变化时安全重置。

## 5. 主题与设计 Token

二期可配置：

- 亮色、暗色、跟随系统。
- 有限预设主题色。
- 默认、紧凑密度。
- 标签页显示。

不提供：

- 任意颜色输入。
- 多套导航布局。
- 动画类型配置。
- 圆角大小配置。
- 灰色模式等装饰开关。

无障碍对比度、键盘焦点、减少动画是默认质量要求，不是装饰偏好。

## 6. 响应式验收

代表视口：

- 桌面：1440px。
- 小桌面/平板横屏：1024px。
- 平板：768px。
- 手机：390px。
- 最小支持：320px。

每个核心流程验证：

- 搜索与重置。
- 新增和编辑。
- 删除与危险确认。
- 权限隐藏。
- 表格横向滚动。
- 抽屉/弹窗关闭与错误状态。
- 所有文字无重叠、截断有明确查看入口。

## 7. 测试策略

开发期：

- Service 契约测试。
- Store 持久化与清理测试。
- 路由白名单与权限测试。
- 当前任务的页面交互测试。
- TypeScript typecheck。

里程碑：

- Vitest 全量。
- ESLint。
- Prettier check。
- Vite build。

后续主题或布局变更：

- 引入 Playwright 前先完成最小 Spike。
- 只覆盖核心流程和代表视口，不复制所有 CRUD 页。
- 最终验收检查控制台错误、中文乱码、溢出和功能降级。

## 8. 明确禁止

- 引入 VXE Table 或同时维护 Ant Table 与 VXE 两套长期列表规范。
- 为统一外观重写所有现有页面。
- 页面直接调用 Axios。
- Store 保存页面局部表单。
- 后端返回任意组件路径并由前端动态 import。
- 同时维护 Ant Table 与 VXE 两套长期列表规范；试点期除外。
- 把完整 Vben 偏好系统复制到 Alpha。
