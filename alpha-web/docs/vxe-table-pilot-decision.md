# VXE Table 单页试点与表格技术决策

## 结论

采用“受控业务场景使用 VXE”的方案，不进行全量迁移，也不建设全局
`AlphaGrid`。本次试点保留在 `system/configs` 页面；普通管理表格继续使用
Ant Design Vue Table。

该页面选择是本次任务的明确范围，覆盖了原阶段计划中“在线用户或操作日志”
的默认页面约束。后续若要调整阶段计划，应单独更新需求源文档。

## 试点范围

- 页面：`src/views/system/configs.vue`。
- 迁移对象：参数列表主表格。
- 保留对象：配置定义抽屉表格、Ant Design Vue 表单、弹窗、抽屉、按钮、消息和操作菜单。
- 不变内容：后端接口、分页 API、权限码、筛选语义、增删改行为和敏感值展示规则。
- VXE 能力：通过与现有角色列表一致的“列设置”浮层完成列显示/隐藏、列顺序、固定左右列；并提供横向和纵向滚动、复选选择、溢出处理和自适应尺寸。
- 批量删除：继续使用页面现有的 Ant Design Vue 工具条、权限码和二次确认流程，不使用 VXE 独立删除入口。

构建仍报告已有的动态导入提示，并提示部分 chunk 超过 500 kB；VXE 试点没有
改变全局 Ant Design Vue 的代码分割策略。该体积结果说明 VXE 适合保留在
复杂表格试点中，但不足以支持全量引入。

## 采用边界

后续页面只有在出现真实的复杂表格需求，并且能证明固定列、虚拟滚动或复杂
表格交互带来明确收益时，才允许单独评估 VXE。第二个页面出现稳定重复规则
之前，不抽取公共 VXE 表格组件。

每次新增 VXE 页面都必须重新检查：

- 业务交互和权限是否保持一致；
- 桌面、平板和手机视口的操作可达性；
- 依赖和路由 chunk 体积；
- 类型检查、测试、lint、格式和生产构建。

## 已知问题

当前工作区使用的 pnpm 版本重新解析了 lockfile，导致 `alpha-web/pnpm-lock.yaml`
包含超出本次新增依赖所需范围的依赖版本重排；功能验证通过，但提交前应由审阅者
重点检查该锁文件差异是否符合仓库的包管理器版本约定。
